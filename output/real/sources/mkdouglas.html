    🚀 I've just shipped bitsandbytes v0.50.0!

    The highlight feature: 4bit inference just got up to 4x faster on NVIDIA GPUs. In particular, batched decoding sees the largest gains thanks to a new set of fused 4bit GEMM kernels.

    The speedups aren't limited to just NVIDIA hardware. AMD also received a much improved 4bit inference path and is now considered stable.

    The CPU backend has significant performance improvements for both x86-64 and ARM64. We also now ship CPU support for Windows on ARM!

    Apple Silicon performance and feature parity continues to improve. The 4bit operations are now accelerated with new Metal kernels. Use the HF `kernels` package and macOS 26+ to enable this.

    There are many more improvements in this release. See the link to the full release notes in the comments!

    We received numerous contributions from the community and employees at     Hugging Face, AMD, Intel, and Qualcomm! Thank you for your support! ❤️

      For over two years, the largest open code dataset was The Stack v2… until today.

      🥞 The Stack v3 is out: the largest open code dataset ever released: 114 TB, 770 languages, 224M repositories, ~5T tokens of deduplicated and filtered source code. Fully open, no restrictively licensed code included.

      The upgrade:
      - v2 (2024): 68 TB raw -> 2 TB / ~550B tokens, 618 languages filtered
      - v3 (2026): 114 TB raw -> 15.9 TB / ~5T tokens, 713 languages filtered

      C++ x15, TypeScript x7.5, Rust x7, Python x4.8. Even the COBOL corner of GitHub got a bigger slice.

      Things that make v3 different:
      1. Contents inline. The one complaint about v2 was "cool dataset, where's the actual code?" v2 shipped file IDs from the Software Heritage graph, and fetching contents was a DIY treasure hunt. v3 is self-contained: sources embedded directly, one row = one repository. Download finishes -> you start training.
      2. Fresh crawl. v2 was a 2023 snapshot of even older crawls. v3 is a direct re-crawl of GitHub at the latest commit, completed by August 2025: 224M repositories, 44B files. Forks were only included if they had 5+ stars.

      Two ways in:
      🥞 stack-v3-train - near-deduplicated, quality-filtered, PII-redacted, contents inline. Point load_dataset at it and go.
      https://lnkd.in/eeFEJ9wu

      🏗 stack-v3-full - the entire 114 TB corpus as an HF Storage Bucket: every duplicate kept with cluster IDs, stubs for excluded files. Roll your own dedup, filters, and mixes.
      https://lnkd.in/eJATmR82

      The record isn't really ours to claim - it's millions of everyone's repositories, neatly stacked. Thanks to every developer who keeps their code public, the BigCode community, and friends who built the infrastructure that made this possible!

      Running AI locally is worth the effort. Your weights, your hardware, no requests leaving the machine. But it means dealing with quantization, and quantization gets complicated fast.
      Pick a GGUF and you're facing names like Q4_K_M, IQ2_XS, TQ1_0, each encoding a different scheme for squeezing a model onto your hardware. Decoding what they actually mean takes bit-level knowledge and a fair amount of C.
      I spent time working through it and wrote a (long) post laying it out clearly, so you can understand what you're choosing and pick a quant consciously instead of guessing.

      Bitsandbytes now has full ROCm/CUDA feature parity. 🔥

      Key improvements:

      1️⃣ 4-bit quantization (blocksize 64 and 32) works on       AMD CDNA GPUs (MI300/MI325). The blocker was wavefront size 64 vs warp size 32. Redesigned the kernel so each wavefront processes multiple quant blocks ( 2 at blocksize=64, 4 at blocksize=32 ) instead of the 1:1 warp-to-block mapping.

      2️⃣ QLoRA and bitsandbytes quantization in vLLM now work on AMD data center GPUs.

      3️⃣ Unified CUDA/HIP kernel sources (removed ~3,300 lines of duplication)-> preventing hip kernels from falling behind as the project evolves.

      4️⃣ Added RDNA 3/3.5/4 build targets.

      💎 Top PRs in the comments.
