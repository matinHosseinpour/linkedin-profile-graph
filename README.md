# LinkedIn profile extraction and graph analysis

Python submission for the technical assessment: extract and store the visible sections of
10 LinkedIn profiles, then analyze the collected data using graphs and centrality.
The delivery contains real captured data and reproducible outputs. The analysis follows the
**graph** option of the assignment; it does not claim a trained predictive ML model.

## Run

Requires Python 3.12+ and a modern browser for the interactive output. Tested on Python 3.14.
From the extracted project directory:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m linkedin_graph extract --manifest output/real/manifest.json --out output/reproduced
```

On Windows, activate with `.venv\Scripts\activate` instead. Dependency installation needs
network access; the included source snapshots can then be processed completely offline.
Open `output/reproduced/interactive.html` in a browser. The submitted version is already in
[output/real/interactive.html](output/real/interactive.html) and can be opened without Python.

**HTML generation is automatic.** Every `extract`, `collect`, `import-session`, `analyze`,
and `demo` run writes `interactive.html`, JSON graphs, PNGs and `report.md` into `--out`.
Rerunning replaces those outputs using the current input; no manual HTML editing is needed.
To analyze an existing dataset or restrict the cohort to explicitly current employees:

```bash
python -m linkedin_graph analyze --input output/real/profiles.json --out output/reanalyzed
python -m linkedin_graph analyze --input output/real/profiles.json --out output/hugging-face --organization "Hugging Face"
```

The optional Jaccard threshold is `--threshold 0.25`. Exit codes are `0` for a successful,
nonempty analysis, `2` for partial/blocked acquisition or an empty cohort, and `1` for an
input/execution error. Partial artifacts are retained with an explicit collection receipt.

## Data source and coverage

The 10 named professional profiles were captured as rendered desktop pages in an existing
ordinary Chrome session on **7 November 2026**. This was browser-visible collection, not a
LinkedIn API export or an unauthenticated HTTP success. The cohort contains nine explicitly
current Hugging Face employees and one Pollen Robotics professional with a visible Hugging
Face affiliation. It is a convenience sample, not a complete organization census.
[selection.md](output/real/selection.md) lists the profiles and selection criteria.

| Required section | Profiles with observed entries | Stored entries |
| --- | ---: | ---: |
| Basic information | 10/10 | Name, headline, location and about fields |
| Work history | 10/10 | 55 |
| Education | 10/10 | 18 |
| Skills | 10/10 | 20 |
| Interests | 10/10 | 18 |
| Activity: posts/interactions | 10/10 | 100 |

Sanitized HTML snapshots are included to make extraction independently reproducible.
`manifest.json` identifies each source; `profiles.json` records its capture timestamp,
SHA-256, acquisition method and section coverage. All submitted profiles have
`is_synthetic=false`. Fictional fixtures are generated by tests, not included as real data.

Coverage means entries were observed in every required section, **not that the complete
profile or activity history is available**. Populated sections are `observed_partial`;
unavailable sections are `unavailable`; unknown dates/counts remain `null`. Activity `text`
is a 90-character preview and `captured_text` retains the body present in the snapshot.
Truncation flags distinguish a shortened preview from an already abbreviated source.
Relative dates remain source text and are not converted to invented publication timestamps.

## Analysis and results

- **Skill affinity:** normalize observed skill names using Unicode NFKC, case folding and
  whitespace normalization. An undirected edge exists when shared skills / union of skills
  (Jaccard similarity) meets the threshold. Its weight is that similarity. The current data
  yields **2 edges**; limited visible skill lists explain the sparse overlap.
- **Observed activity:** explicit repost/comment/reaction records with an identifiable target
  inside the cohort form a separate directed graph. Arrows run from actor to target author;
  weights count captured actions. There are **14 events across 11 directed pairs**.
- **Centrality and groups:** report normalized degree, unweighted shortest-path betweenness,
  weighted strength and greedy weighted-modularity skill communities. The activity graph has
  separate in/out degree and directed betweenness; its colors show weakly connected components.

For example, Thomas Wolf has the highest observed in-degree, with four distinct incoming
counterparties. This identifies a central recipient within this sample; it does not establish
seniority or general influence. Shared skills do not prove collaboration, LinkedIn connections
or reporting lines. Read [report.md](output/real/report.md) for findings, calculations and limits.

The offline Persian/RTL explorer has three views: people, people/posts and shared skills.
Click a person for activity and background, a post for captured text, or an edge for its
supporting actions or shared-skill calculation. It supports text search, person/activity
filters, dragging, zoom, keyboard selection and JSON export of the current view.
It loads no remote scripts/assets; source links open the original LinkedIn pages separately.

## Collect new inputs

For pages already accessible to you in ordinary Chrome, review and run
`linkedin_graph/chrome_session.js` in DevTools on `https://www.linkedin.com`.
Edit its `slugs` list if needed. It visits profiles sequentially, scrolls the rendered pages,
exports a sanitized DOM download, and does not read cookies, passwords or browser storage.
Save the download to a local path, then import it:

```bash
python -m linkedin_graph import-session --input /path/to/linkedin-session-export.json --out output/live
```

Alternatively, create a manifest using the same schema as the included manifest, with relative
HTML paths, canonical profile URLs and `is_synthetic: false`, then use `extract`.
For guest pages that actually permit HTTP collection, supply one HTTPS profile URL per line:

```bash
python -m linkedin_graph collect --urls /path/to/urls.txt --out output/live --interval 5
```

The HTTP collector checks robots rules and stops on access restrictions, login/challenge pages
or rate limiting. It never bypasses those boundaries. LinkedIn may reject all guest requests;
the included snapshots make the submission runnable independently of current access.

## Validate and package

```bash
python -m pip install -e '.[dev]'
python -m pytest -q
python -m ruff check .
python scripts/package.py
```

The packager first rebuilds the real outputs from the included snapshots, then creates
`dist/linkedin-profile-graph.zip` and a SHA-256 sidecar. Only documented source code, tests,
documentation and the real dataset are included. Virtual environments, caches, raw browser
exports, generated demo/preview runs and existing archives are excluded.
